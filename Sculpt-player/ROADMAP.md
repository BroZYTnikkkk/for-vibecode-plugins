# Sculpt Player: план и архив идей

Согласовано 2026-11-06. Делаем по одной функции, сверху вниз. Каждый шаг заканчивается проверкой на телефоне.

## Порядок работ

1. **Переезд на .elyx.** Код разбит на модули без изменения поведения. Свой Java-код (DEX) для тяжёлых мест:
   - сборка очереди (создание `MessageObject`);
   - списки на `RecyclerView` вместо `ListView` через прокси;
   - рисование визуализатора.
2. **Фиксы:**
   - лаги, которые копятся со временем и после смены очередей: сначала замерить память и время кадра, потом чинить;
   - тяжёлый переход с очереди Telegram на свою;
   - старая обложка, когда новая песня уже играет.
3. **Вкладка «Очередь»:**
   - несколько очередей, как в Musicolet: заголовок со списком очередей, у каждой своя песня и позиция;
   - очередь из чата Telegram попадает в список сама, с именем чата;
   - перетаскивание, поиск по очереди, «Сохранить как плейлист» в меню;
   - кнопка очереди убирается из ряда кнопок плеера, кнопка текста остаётся.
   **Переделка вкладки как в Musicolet** (решено 2026-11-07, по скриншотам `01_Queue.png` и меню песни):
   - свой экран на всю высоту над плеером, как Медиатека, без кнопок плеера (мини-плеер потом на все экраны);
   - сверху выпадающий выбор очереди с номером («6. Все песни ⌄») и ✕ «убрать очередь»;
   - ряд: ▶ играть эту очередь, ≡ упорядочить, по центру «позиция / всего» и «⏱ общая длительность», 💾 сохранить как плейлист (кнопка есть, работает с шагом 12), ⋯ меню очереди;
   - строки: ручка перетаскивания «=», обложка, название / автор / альбом, длительность, ⋯; текущая песня в рамке цвета акцента;
   - внизу поиск «Искать в этой очереди…»;
   - список на `RecyclerView` в своём DEX: перетаскивание за ручку, обложки из своего кэша;
   - меню ⋯ песни: шапка с названием и ♡; «Информация о песне», «Убрать из этой очереди»; «Играть после текущей», «Добавить в очередь», «В плейлист»; «Остановиться после этой песни», «Редактировать теги», «Поделиться», «Удалить навсегда» (с подтверждением);
   - переход к автору и альбому не в меню, а по нажатию на автора или альбом в самом плеере (отдельный пункт).
   - баг: при свайпе обложки пальцем визуализатор остаётся на месте, а должен уезжать вместе с обложкой.
4. **Фон плеера сквозь все вкладки:** свечение обложки и ритм видны во вкладках, кнопки плеера там прячутся. Проверить, что текст читается.
5. **Вкладка Mornye** (на месте «Поиска»; поиск по своим песням уходит строкой наверх Медиатеки).
   Устройство (решено 2026-11-07): как Медиатека. Сверху строка «Найти песню для скачивания», под ней пункты-переходы «Загрузки» (с прогрессом), «Метаданные песен», «О Mornye»; экраны внутри с шагом назад. Расширения — кнопкой в правом верхнем углу.
   Части, каждая с проверкой на телефоне:
   1. вкладка, строка поиска в Медиатеке, «О Mornye»: авторы, ссылки, лицензия (раздел ниже);
   2. расширения: перенос `ext_manager.py`, `ext_runtime.py`, `ext_sessions.py`, `downloads.py` из Mornye Player. Формат `.sflx`, официальный реестр `mornyeapp/Mornye-Extension` плюс свои репозитории и установка из файла. Расширения выполняются в WebView (Web Worker) без окна, мост к Python через `127.0.0.1`;
   3. поиск и скачивание песен с прогрессом. Скачанное ложится в `Music/Mornye` на устройстве, общую папку с Mornye Player, и сразу попадает в Медиатеку;
   4. поиск метаданных: найденное пишется в файл только после «Сохранить», с показом «было → станет»; потом пакетно, списком. Решено 2026-11-07:
      - ищут расширения-источники метаданных по приоритету (Deezer, Apple Music, Spotify Web и другие);
      - вход: «Найти теги» в меню песни (Очередь, Медиатека, ⋯ плеера) и «Метаданные песен» во вкладке Mornye — список песен с пустыми или сломанными тегами;
      - экран — редактор с подсказками: сверху варианты из сервисов, выбранный заполняет поля; у каждого поля «было» и редактируемое «станет». Это же «Редактировать теги» (пункт 16);
      - пишутся теги (название, исполнитель, альбом, исполнитель альбома, год, жанр, номера дорожки и диска, ISRC) и обложка; текст песни — позже;
      - без отката: запись после «Сохранить»; для чужих файлов Android один раз спрашивает разрешение.

### Функции Musicolet (по скриншотам 6.14.1)

- **Медиатека шире:**
  - «Не играли»;
  - «Популярные» за неделю, месяц и всё время, со счётчиком прослушиваний;
  - периоды у «Недавно сыгранных» (1, 3, 7, 15, 30, 60 дней);
  - авторы альбома и композиторы;
  - фильтр по автору внутри жанра;
  - папки для сканирования и исключения, скрытие коротких файлов, статистика скана;

- **Воспроизведение:**
  - таймер сна;
  - плавное нарастание при старте и затухание при паузе;
  - без пауз между песнями;
  - запоминание позиции в каждой песне;
  - поведение кнопки «назад»;
  - пауза при отключении наушников, правила продолжения;
  - действия на кнопку гарнитуры (двойное и тройное нажатие).

  - свой 10-полосный эквалайзер с пресетами;

  - реверберация (8 параметров);
  - отдельные настройки для динамика и наушников.
- **Интерфейс и очереди:**
  - порядок и видимость вкладок;
  - выбор пунктов в меню;
  - история поиска;
  - имя файла вместо названия;
  - режимы перемешивания;
  - правило для очереди с тем же именем.

## Справка для работы

### Mornye Link (Mornye 5.3.1)

- **Сервер.** Его поднимает Mornye Desktop, crate на Rust: `rust_backend/crates/link`. Протокол: HTTPS с самоподписанным сертификатом ECDSA P-256, клиент закрепляет его отпечаток.
- **Поиск ПК.** mDNS `_mornye._tcp`, TXT: `v`, `id`, `fp`. Порты 47710–47729. Есть ручной ввод `host:port`.
- **Сопряжение.** На ПК показывается 6-значный PIN, окно сопряжения живёт 5 минут.
  1. `GET /mornye/v1/info`.
  2. `POST /mornye/v1/pair` с proof = HMAC-SHA256(ключ = PIN, `mornye-link-pair-v1:<fp в нижнем регистре>:<deviceId>`) (`lib/services/link/link_protocol.dart:467`).
- **Дальше:** `Authorization: Bearer <ключ устройства>`.
- **Маршруты:**
  - `/rest/*` — OpenSubsonic: stream с Range, download, getCoverArt, getLyricsBySongId;
  - `GET /mornye/v1/ws` — WebSocket;
  - `PUT /mornye/v1/files/<name>` — загрузка с телефона на ПК, до 2 ГиБ;
  - остальное уходит в приложение (`rust_backend/crates/link/src/api.rs:34`).
- **Сообщения WebSocket:** `player.state`, `command`, `open`, `downloads.*`, `collections.changed`, `catalog.changed`, `files.request` / `files.lyrics` / `files.delete`, `transfers.offer` / `status` / `cancel` (`link_protocol.dart:132-180`).

### Метаданные и тексты (Mornye 5.3.1)

- **Поиск песни:** MusicBrainz (поиск записи, ISRC с url-rels), Deezer (`api.deezer.com`: ISRC `search/track?q=isrc:`, текстовый `search/track`, `track/<id>`). Сначала ISRC.
- **Сопоставление:** название, автор, длительность с допуском 10 секунд (`rust_backend/crates/core/src/lyrics/matching.rs:124-146`).
- **Тексты:** LRCLIB, LyricsPlus, прокси Musixmatch, Genius, QQ Music, Apple.
- **Размытие текста:** 0 у текущей строки, 2.4 на соседней, дальше сильнее (`lib/widgets/player_lyrics.dart:1179-1196`); фон — размытая обложка (`lib/widgets/material_player_backdrop.dart`).
- **Пилл качества:** `lib/controllers/player_metadata_controller.dart:399-419`; подсветка при 24 бит или больше 900 кбит/с (`lib/utils/audio_quality_badge_policy.dart`).

### Music Player Actions (cactus), разбор 1.3.0

- **Состав.** Логика во встроенном DEX (`org.pixwet.music.actions.Main`), компаньон `com.exteragram.messenger.mediabridge`. Компаньон читает чужие медиасессии через доступ к уведомлениям и передаёт в Telegram только ключи сессий (Messenger, проверка подписи).
- **Как показывает трек.** В Telegram он строит трек из метаданных сессии и показывает его в родном `MusicPlayerSheet` через рефлексию. `MediaController` этот трек не играет.
- **Свои треки** помечает id ≤ −2 100 000 000; наши id выше этой границы, поэтому конфликта нет. Сессию самого Telegram пропускает по имени пакета.
- **Аудиоданных для визуализатора нет.** Тексты не ищет, подключает только родной вид текста.
- **Вероятные причины багов с аватарками:**
  - поздняя обложка записывается в старый трек без проверки, что он ещё текущий;
  - ключ кэша — название и автор без альбома.
- **Установка компаньона:** через `PackageInstaller` с подтверждением пользователя.
