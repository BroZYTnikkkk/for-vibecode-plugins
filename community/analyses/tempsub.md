# TempSub: кнопка у «Подписаться» и задачи по расписанию

> автор: @itNotMax (@MaxExteraPlugins) · версия 3.1.0 · `.plugin`, ~1080 строк
> файла плагина в репо нет, здесь разбор и короткие выдержки с указанием автора

плагин добавляет рядом с кнопкой «Подписаться» в канале круглую кнопку с календарём. по ней можно подписаться на канал с датой автоотписки (и сразу убрать его в архив). интересен двумя механизмами: встраивание своей вьюхи в нижнюю панель чата и выполнение отложенных действий без фонового сервиса.

---

## кнопка в нижней панели канала

```text
ChatActivity.updateBottomOverlay / onResume ──after──► run_on_ui_thread(_try_attach_button, 300 мс)
      │
      ├── контейнер: bottomChannelButtonsLayout.getContainer()  или bottomOverlayChat (старые версии)
      ├── найти свою кнопку по tag "tempsub_join_button", иначе создать ImageView 40×40
      └── видимость: только если ChatObject.isNotInChat(currentChat) и полоса «Подписаться» видна
```

решения, которые стоит повторить:

- **два хука на одну функцию.** `updateBottomOverlay` вызывается при каждом изменении панели, `onResume` нужен для возврата в чат. оба вызывают одну идемпотентную `_try_attach_button`.
- **задержка 300 мс.** панель перестраивается после хукнутого метода, поэтому кнопка добавляется чуть позже, когда контейнер уже готов.
- **поиск по tag вместо хранения ссылки.** `ChatActivity` создаётся заново для каждого чата, ссылки на старые вьюхи быстро становятся недействительными. найти свою вьюху по `getTag()` среди детей контейнера надёжнее.
- **фолбэк на разные версии.** сначала новое поле `bottomChannelButtonsLayout`, потом старое `bottomOverlayChat`. всё обёрнуто в `try`, чтобы на неизвестной версии плагин просто не показал кнопку.

подвох: флаг «обработчик уже повешен» ставится через `button.setTag(2, "tempsub_clk")`. Android разрешает `setTag(int, Object)` только с id ресурса приложения, на ключе `2` он бросает `IllegalArgumentException`. исключение проглатывается, флаг никогда не ставится, и обработчик вешается заново при каждом вызове. вреда нет (старый просто заменяется), но для своих флагов лучше использовать обычный `setTag(Object)` или словарь в Python.

## отложенные действия без сервиса

у плагина нет своего фонового процесса, поэтому проверка «пора отписаться?» запускается в моменты, когда клиент и так работает:

1. через 3 секунды после загрузки плагина;
2. на `AppEvent.START` и `AppEvent.RESUME` (через 2 секунды);
3. по желанию, периодически каждые N минут через цепочку `run_on_queue(..., PLUGINS_QUEUE, interval_ms)`.

цепочка останавливается модульным флагом `_check_task_scheduled`, который сбрасывается в `on_plugin_unload` и при выключении настройки. каждая итерация первым делом проверяет флаг и не планирует следующую, если он снят.

если телефон был выключен в момент отписки, она выполнится при следующем запуске клиента. для таких задач это нормальная точность.

## хранение и запросы

- список подписок хранится JSON-строкой в одной настройке `subscriptions` (`set_setting(..., reload_settings=True)`, чтобы экран настроек сразу показал изменения);
- подписка: `channels.joinChannel` с `TL_inputChannel(channel_id, access_hash)`, запись сохраняется только в callback при успехе;
- отписка: `channels.leaveChannel`;
- архив: `folders.editPeerFolders` с `folder_id = 1`.

нюанс: в `_check_and_leave_expired` запись удаляется из списка сразу после отправки `leaveChannel`, не дожидаясь ответа. если запрос упадёт, канал останется, а плагин о нём забудет.

## что взять себе

- шаблон «своя кнопка в `ChatActivity`»: хук + задержка + поиск по tag + фолбэк полей;
- проверка отложенных задач на `START`/`RESUME` вместо фонового сервиса.
