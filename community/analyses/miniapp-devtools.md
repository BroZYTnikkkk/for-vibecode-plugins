# MiniApp DevTools: JavaScript внутри WebView клиента

> автор: @xusanboyman200 · версия 3.2.0 · `.plugin`, ~470 строк
> файла плагина в репо нет, здесь разбор и короткие выдержки с указанием автора

плагин встраивает [eruda](https://github.com/liriliri/eruda) (консоль, элементы, сеть, хранилище) в мини-приложения Telegram и включает отладку WebView через `chrome://inspect`. полезен сам по себе для разработки мини-приложений и как пример того, как плагин может выполнять свой JS на страницах внутри клиента.

---

## три хука на системные классы Android

| хук | зачем |
|---|---|
| все конструкторы `android.webkit.WebView` (after) | `WebView.setWebContentsDebuggingEnabled(True)`, чтобы страницу было видно в `chrome://inspect` по USB |
| `WebView.loadUrl` (after) | для http(s)-адресов запускает несколько попыток внедрения скрипта: через 0.2, 0.8, 2 и 4 секунды |
| `WebViewClient.onPageFinished` (after) | внедряет скрипт ещё раз, когда страница загрузилась |

хуки стоят на классах Android, а не Telegram, поэтому не зависят от обфускации клиента. `hook_all_methods(WebViewClient, "onPageFinished", ...)` срабатывает и для подклассов, которые вызывают `super`. подклассы, которые переопределяют метод без `super`, хук не поймает, поэтому и нужен второй путь через `loadUrl` с таймерами.

## внедрение

```python
run_on_ui_thread(lambda: webview.evaluateJavascript(script, None))
```

`evaluateJavascript` можно звать только в UI-потоке. таймеры (`threading.Timer`) запускаются в своих потоках и каждый раз возвращаются через `run_on_ui_thread`.

скрипт написан так, чтобы его можно было выполнить много раз подряд:

- **guard-флаг** `window.__dt32_loaded__`: при повторном выполнении скрипт только проверяет кнопку и выходит;
- **удаление кнопок старых версий** по списку их id и `MutationObserver`, который убирает их, если страница их вернёт;
- **eruda грузится с CDN** (`cdn.jsdelivr.net/npm/eruda`) через `<script>`, после `onload` вызывается `eruda.init`;
- **состояние** (открыта ли панель, её размер) хранится в `localStorage` самой страницы, поэтому переживает перезапуск мини-приложения;
- в вкладку Info добавляются `Telegram.WebApp.platform`, `version` и `initDataUnsafe`.

## нюансы

- **хуки ловят все WebView в клиенте**, не только мини-приложения: например, встроенный браузер. для своих плагинов стоит проверять URL или класс родителя, если нужно ограничиться мини-приложениями.
- **настройки после перезапуска сбрасываются.** значения хранятся в модульном словаре `_config` и меняются только в `on_change`. при загрузке плагин не читает их через `get_setting`, поэтому после перезапуска клиента снова действуют значения по умолчанию, хотя переключатели в настройках показывают сохранённые. правильно в `on_plugin_load` заполнить `_config` из `self.get_setting(...)`.
- **eruda берётся с CDN без версии**, то есть каждый раз грузится последняя. для инструмента разработчика это допустимо, но код со стороннего сервера выполняется в контексте мини-приложения.
- `on_plugin_unload` хуки не снимает вручную. Python-хуки движок снимает сам, а уже внедрённый в открытые страницы JS останется до их перезагрузки.

## что взять себе

- внедрение JS в WebView клиента через `loadUrl`/`onPageFinished` + `evaluateJavascript` в UI-потоке;
- идемпотентный скрипт с guard-флагом;
- `setWebContentsDebuggingEnabled` для отладки своих мини-приложений.
